XENONnT Experiment 
Dual phase Time Projection Chamber(TPC)
Neutron scatters upon entering chamber, creating several spatially distinct energy deposits
Each deposit creates a cluster of ionized electrons, which produce light, known as an S1 signal
These signals are detected by photomultiplier tubes (PMT)
Energized electrons float to the top of the chamber, where they interact with gaseous xenon to once again photoluminesce, known as an S2 signal
The drift time can be calculated by comparing S2 and S1 signal times, which can then be used to reconstruct the depth of the initial interaction
After reconstructing the trigger events, two S2 events are of special importance, the largest (main S2) and the second largest (alt S2)

S2 Tagging Project Description
Main goal is to determine whether set level context between clusters carries relevant information for the sake of S2 tagging, in which case Deep Sets are a viable tool
Hierarchically we have:
Event: 1 neutron scatters within TPC
Cluster: Individual energy deposits, 1 neutron scattering can produce many clusters. 
For each cluster we aim to determine p_main and p_alt, the percent of contribution to the S2 main and S2 alt peaks of each cluster
Cluster features
X,y (cm) - Transverse position
N_electrons_interface (electrons) - ionized electrons that survived drift
Drift_time_mean (ns) - mean drift time (max of 2.2 ms = full TPC drift)
Drift_time_spread (ns) - Longitudinal diffusion sigma 
Event_number (int) - geant4 event index, shared across clusters from one neutron

Deep Sets
Provides a framework for creating any permutation invariant function of the form f(X) = ((x))
For this project, phi is a transformation into our feature vector of dimension L, and rho is our transformation to determining p_main and p_alt
Functionally these are both going to be layers of the neural network
Universal Representation of Permutation-Invariant Functions on Vectors and Tensors
Important takeaway is the size of L, which is the dimension of our “intermediate step” vector: the features extracted from our initial data set to describe the data
Worst case L: O(N^D) ,
 for us N = 118, D=5 giving us a worst case bound of order 10^10
Thankfully for me, a practical L will be in the range of 16-128, as the worst case scenario does not represent the real physics
I will have to sweep L from 8->128 or wherever increasing L does not provide significant gains in accuracy of the model

Today, I focus on why some values of p_alt are greater than 1 (2073 clusters out of 10,259,121 clusters or .02% of clusters)
The write-up assumes that this is due to a numerical artifact in the simulator at short drift times
I examined the drift time of these clusters; the findings seem consistent with the above assumption
Max drift time possible is 2.2 ms or 2.2e6 ns
Median drift time: 12382.0 ns
This is a very short drift time
Drift time means by percentile (0, 25, 50, 75, 100)
[ 3707.  8131. 12382. 17703. 49696.]
Again, very short drift times
I am inclined to believe that this really is caused by some artifacting in the simulation 
The question is what to do with the data: should I just round p_mains down, or remove it? Removing the data would mean eliminating cases with short drift times, and I do not think that would be good. 
The cluster with p_alt > 1 always has a significantly shorter drift time than the other clusters in the events
Electron count doesn't appear significant; there are anomalies in every part of the range of count

After speaking to Pueh, she pointed out that we don’t use the top 13 cm of the TPC for measurements. Likely by cutting out all events with drift time that would have a cluster within those top 13 cm, I can eliminate all p_alt > 1 clusters?

Getting drift velocity from this paper: https://arxiv.org/pdf/2409.08778 
0.675 ± 0.006) mm/μs at 23 V/cm
Using this velocity, we remove all events with a cluster that contains a drift time < 192600 ns
Doing this and then checking the p_alt > 1 clusters, we see that there are now 0 such cases in the remaining data, indicating Pueh may have been correct in her assumption.

Continued developing a deep-set model:
The data is grouped in clusters by event number
Tensors must have the same size, so when we have events with varying amounts of clusters(which we always do), PyTorch is gonna get mad. 
Therefore, we must take the largest amount of clusters in the group, and make all the events have that many clusters through padding with clusters with values of all 0s
This use of padding can trick the model with false data, so we use a mask to differentiate between these fake padded clusters and the real ones with data we want, so that the model can differentiate them later

The actual deep set model was constructed, which does
Applies the phi function to each set
Uses the mask to sum over the clusters
Does the event embedding to each cluster and then applies rho to decode back to p-values
Data and preprocessing
We kept the same input features throughout: x, y, n_electrons_interface, drift_time_mean, and drift_time_spread. The targets are p_main and p_alt.
We applied the 13 cm fiducial cut at the event level using event_number and the minimum drift_time_mean in each event; any event with a cluster above that boundary was removed.
We clipped p_alt to [0, 1] to remove the rare simulator artifact.
We used a train/validation/test split of 70% / 15% / 15%, split by event rather than by cluster so that clusters from the same event never leak across splits.
We fit the StandardScaler on the training split only, then applied it to validation and test.
Dataset and batching
We turned the data into an event dataset, where each item is one variable-size set of clusters belonging to a single event.
We used a custom collate_fn that pads events in a batch to the largest event size in that batch and builds a boolean mask so padded rows can be ignored.
We used standard DataLoaders for train/val/test, with the batch size coming from W&B.
Model architecture
The model is a DeepSet with a per-cluster encoder phi and a decoder rho.
phi is a 2-layer MLP: 5 -> phi_hidden -> latent_dim.
rho is a 2-layer MLP: 2 * latent_dim -> rho_hidden -> 2.
The latent embedding size L was set to 64 for the first run.
The hidden sizes for both phi and rho were set to 64.
The model processes each cluster independently through phi, masks padded clusters, sums across clusters to get an event embedding, then broadcasts that event embedding back to every cluster before decoding.
The output is two values per cluster: one for p_main and one for p_alt.
Loss and optimization
We chose Adam as the optimizer with learning rate 1e-3.
We used binary cross-entropy with logits rather than MSE, because the targets are probability-like soft labels in [0, 1].
We used a masked BCE loss so padded clusters do not contribute to the objective.
In the forward path, probabilities are recovered with torch.sigmoid(logits) for metrics and reporting, while training stays in logit space for numerical stability.
Training and evaluation
The training loop runs for 10 epochs.
Every epoch computes train and validation loss, plus ROC-AUC for p_main and p_alt.
We keep the best model by validation loss, not by training loss or AUC.
After training, we restore the best checkpoint and run a final test evaluation.
Metric-wise, we used cluster-level ROC-AUC for p_main and p_alt.
Runtime / hardware choices we discussed
Because this is running on a GTX 1080, we decided to favor a smaller batch size, pin_memory, non_blocking=True transfers, and a few DataLoader workers so the GPU stays fed.
We also decided to save the best checkpoint locally during training, since the job runs on a remote server.
